TOOL 1Whisper：會議逐字稿

是什麼

Whisper 係 OpenAI 於 2022 年開源之語音辨識（Automatic Speech Recognition, ASR）模型，以 68 萬小時多語言語料訓練，中文辨識品質屬開源方案第一梯隊。關鍵特性是可完全本機執行：錄音檔不需上傳任何雲端服務，對涉及內部討論、人事、預算之會議錄音，符合公務資料保護要求。

三種使用路徑

路徑形式適合對象備註
A. Buzz（建議入門）圖形介面軟體，拖放即轉不想碰指令列者開源免費，Windows／Mac 皆有，內建 Whisper
B. openai-whisper指令列（本手冊主線）願意用終端機者官方版，指令最單純
C. faster-whisper指令列／Python大量、長時間錄音速度約為官方版四倍、記憶體減半
建議：先用路徑 A（Buzz）驗證效果與需求；確認要常態使用後，改路徑 B 或 C 以便批次處理與後續自動化串接。

路徑 A：Buzz 圖形介面（零指令）

WSP-A1

下載安裝

至 GitHub 專案頁 github.com/chidiwilliams/buzz 的 Releases 區下載對應版本（Windows 選 .exe，Mac 選 .dmg），依一般軟體安裝流程完成。

WSP-A2

首次設定

  • 開啟 Buzz → File → Import Media File，選擇會議錄音檔（支援 m4a、mp3、wav、mp4 等）。
  • Model 選 Whisper、大小選 Medium（中文品質與速度的平衡點）。
  • Language 選 Chinese；Task 選 Transcribe。
  • 首次執行會自動下載模型檔（約 1.5 GB），僅需一次。
WSP-A3

匯出逐字稿

轉錄完成後可匯出 TXT（純文字）或 SRT（含時間戳）。含時間戳版本便於回查原始錄音段落，建議兩種都存。

路徑 B：指令列版（可批次、可自動化）

WSP-B1

安裝前置環境

需要 Python 3.9 以上與 FFmpeg（音訊解碼用）。

# Windows（先安裝 Python：python.org 下載，安裝時勾選 Add to PATH）
winget install ffmpeg

# macOS（先安裝 Homebrew：brew.sh）
brew install ffmpeg
WSP-B2

安裝 Whisper

pip install -U openai-whisper

驗證安裝：執行 whisper --help 出現說明文字即成功。

WSP-B3

轉錄第一份錄音

whisper 0711科務會議.m4a --language Chinese --model medium \
  --initial_prompt "以下是臺灣消防機關的繁體中文會議逐字稿，內容涉及緊急救護政策。" \
  --output_format txt --output_format srt
  • --initial_prompt 是關鍵技巧：Whisper 的中文輸出預設常出現簡體字，以繁體中文提示語引導後，輸出將穩定為繁體，並提高專有名詞辨識率。可在提示語中加入常用術語（如「緊急醫療救護法、EMT、救護技術員」）。
  • 首次執行會下載模型，之後離線可用。
  • 輸出檔與錄音檔同資料夾，含 .txt 與 .srt。
WSP-B4

批次處理整個資料夾

# 一次轉錄資料夾內全部錄音
whisper *.m4a --language Chinese --model medium --output_dir ./逐字稿

模型大小選擇

模型檔案大小建議記憶體相對速度中文品質適用
small約 460 MB2 GB快可用，專有名詞易錯快速草稿
medium約 1.5 GB5 GB中良好（建議預設）日常會議紀錄
large-v3約 3 GB10 GB慢最佳重要會議、口音重、收音差
速度參考：一般辦公筆電（無獨立顯卡）以 medium 模型轉錄一小時錄音，約需 30 至 60 分鐘；有 NVIDIA 顯卡可縮短至數分鐘。長錄音建議改用 faster-whisper（pip install faster-whisper）或掛機夜間執行。

完整工作流：從錄音到會議紀錄

會議錄音→ Whisper 逐字稿→ Claude 整理→ 三段式會議紀錄

逐字稿本身不是終點。將 .txt 交給 Claude（可搭配您既有的會議紀錄 Skill），指示「依決議事項、討論摘要、待辦分工整理為會議紀錄」，即完成從錄音到正式文書的完整鏈路。注意：機敏會議之逐字稿是否可交付雲端 AI 整理，須依機關資安規範判斷；不可者，僅止於本機逐字稿。

TOOL 2n8n：行政流程自動化

是什麼

n8n 是開源工作流自動化平台，以「節點（node）」視覺化串接各項服務：某事件發生（觸發）→ 依序執行處理步驟（動作）。可理解為不需寫程式的自動化排程員，支援四百餘種服務整合（Gmail、Google 日曆、試算表、RSS、HTTP API 等），並內建 AI 節點可呼叫 Claude 等模型。自架版免費，資料留在自己機器。

核心概念（五個名詞）

名詞意義類比
Workflow一條完整的自動化流程一份標準作業程序（SOP）
Node流程中的單一步驟SOP 中的一個作業項目
Trigger啟動流程的條件（定時、收到郵件、表單送出）SOP 的啟動時機
Credential各服務的登入授權（如 Gmail 授權）各系統的帳號憑證
Execution流程每一次的實際執行紀錄執行日誌，可回查除錯

安裝部署

N8N-01

選擇部署方式

  • Docker 自架（建議）：資料留本機，免費，升級容易。本手冊採此路徑。
  • npm 安裝：已有 Node.js 環境者可用 npx n8n 快速試用。
  • n8n Cloud 官方雲端：免安裝但需付費，且資料經境外伺服器，公務情境不建議。
N8N-02

安裝 Docker Desktop

至 docker.com 下載 Docker Desktop（Windows／Mac），安裝後啟動。Windows 首次安裝若提示需 WSL 2，依畫面指示完成即可。

N8N-03

啟動 n8n

# 建立資料儲存區（工作流與憑證存放處，僅首次需要）
docker volume create n8n_data

# 啟動 n8n
docker run -d --name n8n --restart unless-stopped \
  -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

開啟瀏覽器進入 http://localhost:5678，首次進入依畫面建立本機管理帳號。

N8N-04

認識操作介面

  • 左側為工作流清單；點 Create Workflow 進入畫布。
  • 畫布中點 ＋ 新增節點，第一個節點必為 Trigger。
  • 每個節點可單獨按 Execute step 測試，即時查看輸出資料。
  • 右上角 Active 開關：開啟後流程才會依觸發條件自動執行。

實作範例：國際 EMS 動態每週自動彙整

以下建立第一條具實用價值的工作流：每週一上午 8 時，自動抓取國際 EMS 新聞來源，由 AI 摘要後寄送至您的信箱，取代人工逐站瀏覽。

每週一 08:00→ 讀取 RSS→ 過濾七日內→ AI 摘要→ 寄送 Gmail
N8N-11

建立定時觸發

新增 Schedule Trigger 節點 → Trigger Interval 選 Weeks → 星期選 Monday、時間設 08:00。

N8N-12

讀取新聞來源

新增 RSS Read 節點，URL 填入 EMS 新聞來源，例如 https://www.ems1.com/rss（EMS1，美國最大 EMS 新聞站）。需多來源時，可並列多個 RSS Read 節點後以 Merge 節點合併。

N8N-13

過濾近七日文章

新增 Filter 節點，條件設定：欄位 {{ $json.pubDate }} → 運算子選 Date「is after」→ 值填 {{ $now.minus(7, 'days') }}。

N8N-14

AI 摘要

新增 Anthropic 節點（或 Basic LLM Chain）：

  • Credential 填入 Anthropic API 金鑰（於 console.anthropic.com 申請）。
  • Prompt 範例：「以下為本週國際 EMS 新聞標題與摘要，請以繁體中文整理為條列式週報，每則含一句重點與政策相關性註記：{{ $json.title }}－{{ $json.contentSnippet }}」。
省成本替代：不接 AI 亦可，直接跳至下一步將標題與連結原文寄出，同樣省去逐站巡覽時間。
N8N-15

寄送郵件

新增 Gmail 節點 → Operation 選 Send → 首次使用依畫面完成 Google 帳號 OAuth 授權 → 收件人填自己，主旨如「國際 EMS 週報 {{ $now.format('yyyy-MM-dd') }}」，內文帶入前節點輸出。

N8N-16

測試與啟用

按 Execute Workflow 手動跑一次全流程，確認信箱收到週報後，將右上角 Active 切為開啟。此後每週一自動執行，可於 Executions 頁查看每次執行紀錄。

公務情境延伸應用

應用觸發流程效益
採購時程提醒每日定時讀 Google 試算表採購期程 → 判斷距截止日 ≤ 7 天 → 寄提醒招標、開標、驗收節點不漏
預算執行月報每月 1 日讀執行率試算表 → AI 產出摘要段落 → 寄承辦與科長月報初稿自動化
研討會報名彙整表單送出時Google 表單 → 寫入試算表 → 自動回信報到資訊免人工登打與逐一回覆
國際期刊監測每週PubMed／期刊 RSS → 關鍵字過濾（prehospital、TECC）→ 摘要寄送政策研究情蒐常態化
錄音自動轉逐字稿資料夾出現新檔見下節「兩者串接」錄音丟資料夾即完成

進階：n8n × Whisper 串接

兩工具熟練後，可組成全自動逐字稿產線：指定一個「會議錄音」資料夾，n8n 監測到新檔即呼叫本機 Whisper 轉錄，完成後通知您。

錄音存入資料夾→ Local File Trigger→ Execute Command 呼叫 whisper→ 逐字稿產出→ Email 通知
  • Local File Trigger 節點監看指定資料夾之新增檔案（需於 Docker 啟動指令加掛該資料夾：-v /本機路徑:/data）。
  • Execute Command 節點執行 whisper 指令，帶入觸發取得的檔名。
  • 此屬進階題，建議兩項工具各自熟練一個月後再實作。

公務資安須知

導入前務必確認機關資安規範。以下為通用原則，實際適用依內政部及消防署資通安全規定辦理。
面向原則
Whisper 本機轉錄全程離線運算，錄音與逐字稿不出機，資安風險最低；此為其相對雲端轉錄服務之核心優勢。
逐字稿後續處理將逐字稿交付雲端 AI（Claude 等）整理前，先去識別化並確認內容非屬機敏；機敏會議僅止於本機處理。
n8n 部署位置自架於個人電腦或機關內網主機，勿使用境外雲端版處理公務資料。
n8n 憑證管理Gmail、API 金鑰等憑證存於本機 n8n，設定管理帳號強密碼；離開座位鎖定電腦。
流經外部 API 之資料工作流中凡經過外部服務（AI 摘要、雲端表單）之節點，內容以公開或低敏資訊為限。
公務帳號分際串接郵件建議先以個人測試帳號驗證流程，涉公務信箱前先確認機關政策。

建議導入順序

階段時程目標驗收標準
第一週1–2 小時Buzz 安裝，完成第一份會議逐字稿一份 30 分鐘以上錄音之可用逐字稿
第二週2 小時指令列 Whisper + initial_prompt 繁中優化；逐字稿交 Claude 產會議紀錄錄音→正式會議紀錄全鏈路走通
第三週2–3 小時Docker 安裝 n8n，完成 EMS 週報工作流週一自動收到第一封週報
第四週起每週 1 小時逐條增建工作流（採購提醒、期刊監測）每月新增一至二條穩定運作之流程
第二個月選做n8n × Whisper 串接，資料夾自動轉錄錄音入夾即自動產出逐字稿

核心心法：不追求一次到位。Whisper 每場會議即回收時間；n8n 每條穩定的工作流都是永久性的行政產能，累積十條後，等同多出一位不休假的助理。
