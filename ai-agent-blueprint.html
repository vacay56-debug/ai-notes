AI Agent 完整架構藍圖 THE COMPLETE AI AGENT BLUEPRINT

一套框架 ・ 四個層次 ・ 零混亂

本圖說明代理式人工智慧（AI Agent）系統的完整組成架構：以核心代理迴圈（Agent Loop）為引擎，由技能（Skills）、模型上下文協定（Model Context Protocol, MCP）、子代理（Subagents）與掛勾（Hooks）四個層次分工協作，再以 CLAUDE.md 提供常駐脈絡、以外掛（Plugin）統一打包發布。

FIG. 0

核心代理迴圈

CORE AGENT LOOP — 所有元件圍繞此引擎運轉

代理的本質是一個持續循環的決策引擎：大型語言模型（Large Language Model, LLM）作為「代理核心」，一端連接指令與領域知識，另一端連接外部工具與資料，反覆執行以下四個階段，直到任務完成。

STEP 1感知 Perceive
接收輸入、上下文與查詢，建立對任務的理解。
STEP 2推理 Reason
LLM 規劃下一步行動：該用什麼工具、走哪條路徑。
STEP 3行動 Act
執行工具呼叫、程式碼或應用程式介面（Application Programming Interface, API）請求。
STEP 4觀察 Observe
評估執行結果，回饋至下一輪感知，形成閉環。

FIG. 1–4

四層架構

SKILLS / MCP / SUBAGENTS / HOOKS — 各司其職
LAYER 1

技能 —— 智慧層

SKILLS — The Intelligence Layer
  • 可重複使用的指令模組，內含指令、腳本、資源與範本
  • 由代理按需載入（On-Demand），非常駐佔用
  • 採漸進式揭露（Progressive Disclosure）：代理先讀取中繼資料（metadata），確認相關後才載入完整內容
  • 運作流程：任務出現 → 代理偵測相關技能 → 按需載入 → 執行工作流
  • 如同 AI 的「訓練手冊」——在對的時機抽出對的那一本
SKILLS ＝ 知識（KNOWLEDGE）
LAYER 2

模型上下文協定 —— 連線層

MCP — The Connection Layer
  • 標準化協定，讓代理連接外部服務與資料來源
  • 常見伺服器：GitHub、Notion、Slack、GitLab、OpenAI、AWS、資料庫等
  • 每個 MCP 伺服器提供一組工具，例如：Server 1（GitHub 程式庫）、Server 2（資料庫查詢）、Server 3（Slack 訊息）
  • 解決「每個服務各寫一套整合」的碎片化問題，一次接上、處處可用
MCP ＝ 能力（ABILITY）
LAYER 3

子代理 —— 執行層

SUBAGENTS — The Execution Layer
  • 將任務委派給多個獨立的子代理，各自隔離執行、互不干擾
  • 範例編組：程式碼審查員（工具：Read、Grep）、研究員（工具：Search、Fetch）、部署員（工具：Bash、SSH）
  • 每個子代理擁有自己的上下文與最小必要工具集，符合權限最小化原則
  • 主代理負責統籌與整合，如同承辦人分派業務給各股
SUBAGENTS ＝ 委派（DELEGATION）
LAYER 4

掛勾 —— 控制層

HOOKS — The Control Layer
  • 在特定事件觸發時自動執行的確定性規則，不依賴 LLM 判斷
  • 四種類型：Pre-Tool（工具執行前）、Post-Tool（工具執行後）、On-Edit（檔案變更時）、On-Notification（警示與日誌）
  • 典型流程：使用者編輯程式碼 → 觸發掛勾 → 自動執行格式化 → 執行安全掃描 → 攔截不安全的提交（commit）
  • 是整套架構的「保險絲」與「品管站」
HOOKS ＝ 自動化（AUTOMATION）

檔案系統與打包層

CLAUDE.md ＋ PLUGINS — 常駐脈絡與統一封裝

CLAUDE.md 是唯一的「常駐錨點」（Always-On Anchor）：專案脈絡、組織資訊等永遠在場的內容寫在這裡；其餘知識拆為 Skill 1、Skill 2、Skill 3 與參考文件（Reference docs），按需載入。三句話總結分工——Skills 決定「該知道什麼」，MCP 決定「如何連接」，Hooks 決定「何時自動化」。

外掛（Plugin）是打包層：將 Skills、MCP、Hooks、Subagents 四種元件封裝為單一套件，一次安裝、完整佈署，便於團隊內部或跨組織散布標準化的代理能力。

實際運作範例

REAL-WORLD EXAMPLE — 一次競品分析任務的完整流程
CLAUDE.md 載入啟動即注入專案脈絡與公司資訊，代理知道「自己在替誰、為何而做」。
Skill 啟動偵測任務屬性，按需載入「競品分析」（competitive-analysis）框架。
MCP 觸發連接 Google Drive，搜尋過往簡報與內部文件作為分析基礎。
子代理一：市場研究員獨立蒐集外部市場資料，不佔用主代理上下文。
子代理二：技術分析員平行審閱程式庫（repositories），產出技術面評估。
Hook 觸發輸出自動格式化並執行檢查工具（linter），確保交付品質一致。

NOTE

設計要旨

DESIGN PRINCIPLES — 三條讀後即用的原則

一、分層即分權。知識（Skills）、連線（MCP）、執行（Subagents）、控制（Hooks）各層獨立演進，任一層更換不牽動其他層，是「零混亂」的來源。

二、按需載入優於全量堆疊。漸進式揭露讓上下文視窗只承載當下必要的內容，成本更低、判斷更準。

三、確定性的交給 Hooks，判斷性的交給 LLM。凡是「每次都要、規則固定」的動作，一律下沉為掛勾自動化，把模型的推理能力留給真正需要判斷的環節。
