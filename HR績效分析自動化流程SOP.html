SECTION 00

總則

建置前應先確認目的、適用範圍、權責分工及環境前置作業，避免流程上線後產生資料權責不清或授權不足之情形。

一、目的

  • 提升效率：以自動化流程取代人工彙整與繕打，縮短報告產製工時。
  • 資料正確：統一資料來源與計算公式，降低人為轉錄錯誤。
  • 即時掌握：報告可於評核期間結束後即時產出，支援管理決策。
  • 溝通順暢：分析結果自動寄送權責主管與同仁，資訊傳遞零時差。

二、適用範圍

適用於單位內定期（月／季／年）辦理之員工績效評核作業，包含資料搜集、指標運算、質性論述生成及結果通知等作業環節。不適用於涉及敘薪、獎懲或人事處分之最終決定；AI 生成內容僅供管理參考，最終判斷仍應由權責主管為之。

三、權責分工

角色權責事項權限層級
流程主辦人表單設計、指標權重維護、流程執行結果複核試算表／指令碼專案「編輯者」
系統管理員API 金鑰保管、觸發器設定、異常排除、版本控管指令碼專案「擁有者」
評核者（主管）填寫評核表單、確認分析報告內容表單填寫權限
資訊安全窗口個資盤點、存取權限稽核唯讀稽核權限

四、前置作業

確認 Google Workspace 帳號權限

確認帳號可建立表單、試算表與 Apps Script 專案，且組織政策未封鎖外部 API 呼叫（UrlFetchApp）。

申請 Gemini API 金鑰

至 Google AI Studio 建立 API 金鑰，並確認所選模型之免費或計費額度足敷單位使用量。

建立專屬雲端硬碟資料夾

建立「績效分析自動化」資料夾，將表單、試算表、輸出報告集中管理，並限縮共用對象為權責人員。

完成個資盤點

依《個人資料保護法》盤點欄位，確認蒐集之特定目的與告知事項（詳附錄 A）。

STAGE 01 ／ GOOGLE FORM

績效資料搜集

透過 Google 表單蒐集績效資料，達到快速、標準化之目的。表單欄位即為後續運算之資料結構，設計錯誤將導致全流程返工，應於此階段一次定案。

作業步驟

建立表單並設定基本資訊

表單標題採「{年度}{期別}績效評核表」格式；於說明欄載明蒐集目的、使用範圍及保存期限。

設定必填識別欄位

包含「受評人姓名」「員工編號」「所屬部門」「評核期間」「評核者」。員工編號為後續比對鍵（Key），務必設為必填並以「簡答＋規則驗證」限制格式。

設定量化指標欄位

採線性刻度（1–5 分）建立五項指標，避免使用開放式數字輸入，以確保分數區間一致。

設定質性描述欄位

建立「具體事蹟」與「待改善建議」兩個長答題欄位，作為 Gemini 生成論述之語料來源。

限制填寫身分與次數

勾選「僅限組織內使用者」及「限填一次」，並開啟「蒐集電子郵件地址」以利追溯。

試填驗證

由主辦人試填 2–3 筆測試資料，確認欄位順序與必填規則無誤後始正式發布。

注意

表單發布後不得任意增刪或調整欄位順序。任一變更均會於試算表新增欄位並打亂欄位索引，導致 Apps Script 讀取錯誤。確需變更時，應改版為新表單並同步更新指令碼之欄位對照設定。

檢核點
  • 必填欄位是否全數設定完成？
  • 員工編號格式驗證是否生效？
  • 是否限制組織內填寫並蒐集電子郵件地址？
  • 表單說明是否已載明個資蒐集告知事項？

STAGE 03 ／ GOOGLE APPS SCRIPT

自動化分析

以 Google Apps Script 自動處理資料、計算指標並產出分析結果。本階段程式碼分為設定、彙整、分析、寄送、主控五個檔案，便於維護與版本控管。

作業步驟

開啟指令碼編輯器

於試算表選單點選「擴充功能 → Apps Script」，將專案命名為「績效分析自動化」。

設定指令碼屬性

於「專案設定 → 指令碼屬性」新增 GEMINI_API_KEY，值為 Gemini API 金鑰。嚴禁將金鑰直接寫入程式碼。

依序建立程式檔案

新增 01_設定.gs、02_彙整.gs、03_分析.gs、04_寄送.gs、05_主控.gs，並貼入下列程式碼。

執行授權

首次手動執行 buildSummary 時，依提示完成 OAuth 授權，授予試算表、外部服務與 Gmail 存取權限。

單元驗證

以測試資料執行 buildSummary，核對「彙整」表加權總分與人工試算結果是否一致。

01_設定.gs

01_設定.gs　／　全域參數與共用函式
/** 全域設定：工作表名稱、指標權重、郵件主旨樣板 */
const CFG = {
  RESP_SHEET: '表單回應 1',
  CONF_SHEET: '設定',
  SUM_SHEET : '彙整',
  LOG_SHEET : '執行紀錄',
  WEIGHTS   : { '工作品質':0.30, '時效達成':0.25, '團隊協作':0.20,
                '創新改善':0.15, '出勤紀律':0.10 },
  GRADE     : [[4.5,'優等'],[4.0,'甲等'],[3.0,'乙等'],[0,'待加強']]
};

/** 取得試算表物件 */
function ss_() { return SpreadsheetApp.getActiveSpreadsheet(); }

/** 讀取「設定」工作表，回傳鍵值物件 */
function conf_() {
  const rows = ss_().getSheetByName(CFG.CONF_SHEET).getDataRange().getValues();
  const o = {};
  rows.forEach(r => { if (r[0]) o[String(r[0]).trim()] = String(r[1]).trim(); });
  return o;
}

/** 自指令碼屬性取得 API 金鑰（不得寫死於程式碼） */
function apiKey_() {
  const k = PropertiesService.getScriptProperties().getProperty('GEMINI_API_KEY');
  if (!k) throw new Error('尚未設定 GEMINI_API_KEY，請至專案設定新增指令碼屬性。');
  return k;
}

/** 寫入執行紀錄 */
function log_(level, msg) {
  const sh = ss_().getSheetByName(CFG.LOG_SHEET);
  sh.appendRow([new Date(), level, String(msg).slice(0, 500), Session.getActiveUser().getEmail()]);
}

/** 依加權總分判定等第 */
function grade_(score) {
  for (const [min, name] of CFG.GRADE) if (score >= min) return name;
  return '待加強';
}

02_彙整.gs

02_彙整.gs　／　讀取回覆、計算指標、寫入彙整表
/**
 * 讀取表單回覆，計算加權總分、部門平均與排名，寫入「彙整」工作表。
 * @return {Array<Object>} 彙整後之資料陣列，供後續分析使用。
 */
function buildSummary() {
  const c = conf_();
  const period = c['評核期間'];
  const alert = Number(c['低分警示門檻'] || 3);

  const data = ss_().getSheetByName(CFG.RESP_SHEET).getDataRange().getValues();
  const head = data.shift();
  const idx  = n => head.indexOf(n);

  // 過濾本期資料並計算加權總分
  const rows = data
    .filter(r => String(r[idx('評核期間')]).trim() === period)
    .map(r => {
      const scores = {};
      let total = 0;
      for (const [k, w] of Object.entries(CFG.WEIGHTS)) {
        const v = Number(r[idx(k)]) || 0;
        scores[k] = v;
        total += v * w;
      }
      return {
        id    : r[idx('員工編號')],
        name  : r[idx('受評人姓名')],
        dept  : r[idx('所屬部門')],
        scores: scores,
        total : Math.round(total * 100) / 100,
        merit : r[idx('具體事蹟')] || '',
        improve: r[idx('待改善建議')] || ''
      };
    });

  if (!rows.length) throw new Error('查無「' + period + '」之表單回覆資料。');

  // 計算部門平均
  const deptAvg = {};
  rows.forEach(x => (deptAvg[x.dept] = deptAvg[x.dept] || []).push(x.total));
  Object.keys(deptAvg).forEach(d => {
    const a = deptAvg[d];
    deptAvg[d] = Math.round(a.reduce((s, v) => s + v, 0) / a.length * 100) / 100;
  });

  // 部門內排名（同分同名次）
  Object.keys(deptAvg).forEach(d => {
    rows.filter(x => x.dept === d)
        .sort((a, b) => b.total - a.total)
        .forEach((x, i, arr) => {
          x.rank = (i > 0 && arr[i-1].total === x.total) ? arr[i-1].rank : i + 1;
        });
  });

  // 寫回「彙整」工作表
  const sh = ss_().getSheetByName(CFG.SUM_SHEET);
  sh.clear();
  const keys = Object.keys(CFG.WEIGHTS);
  sh.appendRow(['員工編號','姓名','部門', ...keys,
                '加權總分','部門平均','部門排名','等第','關注標記']);
  sh.getRange(2, 1, rows.length, keys.length + 8).setValues(
    rows.map(x => [x.id, x.name, x.dept, ...keys.map(k => x.scores[k]),
                   x.total, deptAvg[x.dept], x.rank, grade_(x.total),
                   x.total < alert ? '★' : ''])
  );
  sh.setFrozenRows(1);

  rows.forEach(x => { x.deptAvg = deptAvg[x.dept]; x.grade = grade_(x.total); });
  log_('INFO', '彙整完成，計 ' + rows.length + ' 筆。');
  return rows;
}
設計說明

本階段刻意將「讀取—運算—寫入」與「AI 生成」分離。彙整結果先落地於工作表，即使後續 Gemini 呼叫失敗，量化數據仍完整保留，承辦人可據以人工出具報告，符合業務不中斷之要求。

檢核點
  • 加權總分是否與人工試算一致（抽驗至少 3 筆）？
  • 部門平均與排名計算是否正確處理同分情形？
  • 查無資料時是否正確拋出例外並記錄於「執行紀錄」？
STAGE 04 ／ GEMINI API

分析論述

串接 Gemini API 就量化結果生成質性分析論述與管理洞察，提升報告品質與深度。輸出採結構化 JSON，確保後續套版穩定。

作業步驟

確認金鑰與模型

確認指令碼屬性已設定 GEMINI_API_KEY，且「設定」表之模型名稱為有效模型代碼。

建立提示詞（Prompt）樣板

提示詞須包含角色設定、資料脈絡、分析框架及輸出格式四要素，並明確要求僅回傳 JSON。

實作 API 呼叫與重試機制

使用 UrlFetchApp.fetch 並啟用 muteHttpExceptions，針對 429／5xx 狀態碼採指數退避（Exponential Backoff）重試 3 次。

去識別化處理

送出前將姓名替換為代碼，僅回傳後於本地還原，避免個人識別資料外送（詳附錄 A）。

人工複核

首次上線及每次調整提示詞後，須由主辦人逐段複核生成內容之正確性與用語妥適性。

03_分析.gs

03_分析.gs　／　提示詞組裝、API 呼叫與重試
/** 組裝提示詞：角色、脈絡、框架、輸出格式四要素 */
function buildPrompt_(rows, period) {
  // 去識別化：以代碼取代姓名與員工編號
  const masked = rows.map((x, i) => ({
    代碼: 'E' + String(i + 1).padStart(3, '0'),
    部門: x.dept, 各項得分: x.scores, 加權總分: x.total,
    部門平均: x.deptAvg, 部門排名: x.rank, 等第: x.grade,
    具體事蹟: x.merit, 待改善: x.improve
  }));

  return [
    '你是人力資源管理分析師，負責撰寫組織績效分析報告。',
    '以下為 ' + period + ' 績效評核彙整資料（已去識別化）：',
    JSON.stringify(masked, null, 0),
    '',
    '請依下列框架分析：(1) 整體績效分布與集中趨勢；(2) 部門間差異；',
    '(3) 五項指標之相對強弱；(4) 需管理關注之樣態（不指名個人）；',
    '(5) 可執行之管理建議。',
    '',
    '撰寫要求：使用繁體中文（臺灣用語）；文風精簡客觀；以資料佐證，',
    '不得臆測未提供之資訊；避免對個人作出人格性評價。',
    '',
    '僅輸出 JSON，不得包含說明文字或程式碼標記，格式如下：',
    '{"overview":"整體概述 150 字內","distribution":"分布分析",' +
    '"strengths":["優勢1","優勢2"],"risks":["風險1","風險2"],' +
    '"actions":[{"item":"建議事項","owner":"權責單位","priority":"高/中/低"}]}'
  ].join('\n');
}

/**
 * 呼叫 Gemini API，含指數退避重試。
 * @return {Object} 解析後之分析結果物件
 */
function analyze(rows) {
  const c = conf_();
  const model = c['模型名稱'] || 'gemini-2.0-flash';
  const url = 'https://generativelanguage.googleapis.com/v1beta/models/' +
              model + ':generateContent?key=' + apiKey_();

  const payload = {
    contents: [{ role: 'user', parts: [{ text: buildPrompt_(rows, c['評核期間']) }] }],
    generationConfig: { temperature: 0.3, maxOutputTokens: 2048,
                        responseMimeType: 'application/json' }
  };

  let lastErr = '';
  for (let i = 0; i < 3; i++) {
    const res = UrlFetchApp.fetch(url, {
      method: 'post', contentType: 'application/json',
      payload: JSON.stringify(payload), muteHttpExceptions: true
    });
    const code = res.getResponseCode();

    if (code === 200) {
      const body = JSON.parse(res.getContentText());
      const text = body.candidates[0].content.parts[0].text
                     .replace(/```json|```/g, '').trim();
      return JSON.parse(text);
    }
    if (code !== 429 && code < 500) throw new Error('API 錯誤 ' + code + '：' + res.getContentText());

    lastErr = code;
    Utilities.sleep(Math.pow(2, i) * 2000);   // 2s → 4s → 8s
  }
  throw new Error('Gemini API 重試 3 次仍失敗，最後狀態碼：' + lastErr);
}
品質管控

AI 生成內容僅供管理參考，不得作為考績評定或人事處分之直接依據。報告寄送前應由主辦人複核，如發現與量化數據不符或用語不當者，應修正後始得發送，並將修正情形回饋至提示詞版本紀錄。

檢核點
  • 回傳內容是否可成功解析為 JSON（無 Markdown 標記殘留）？
  • 論述內容是否與彙整表數據一致，未出現虛構數字？
  • 送出資料是否已完成去識別化？
  • 重試機制於模擬 429 時是否正常運作？
STAGE 05 ／ GMAIL

寄送結果

自動寄送分析結果予權責主管與同仁，即時掌握績效狀況。郵件採 HTML 格式，內含摘要、統計表與管理建議三段。

作業步驟

確認收件者清單

自「設定」表讀取收件者，並確認均為組織內信箱；外部信箱須經權責主管書面同意始得列入。

組裝 HTML 郵件

以行內樣式（Inline CSS）撰寫，避免部分郵件用戶端不支援 <style> 區塊。

先寄送測試信

正式發送前，先寄送至主辦人本人信箱檢視版面與中文編碼。

正式發送並留存副本

以密件副本（BCC）方式副知業務檔案信箱，作為留存紀錄。

04_寄送.gs　／　HTML 郵件組裝與寄送
function sendReport(rows, ai) {
  const c = conf_();
  const period = c['評核期間'];
  const to = c['收件者'];
  const avg = Math.round(rows.reduce((s, x) => s + x.total, 0) / rows.length * 100) / 100;

  const tdS = 'style="padding:8px 10px;border-bottom:1px solid #e0e0e0;font-size:14px"';
  const thS = 'style="padding:8px 10px;background:#14664A;color:#fff;font-size:13px;text-align:left"';

  const tableRows = rows
    .sort((a, b) => b.total - a.total)
    .map(x => '<tr><td '+tdS+'>'+x.name+'</td><td '+tdS+'>'+x.dept+
              '</td><td '+tdS+'>'+x.total+'</td><td '+tdS+'>'+x.grade+
              '</td><td '+tdS+'>'+x.rank+'</td></tr>').join('');

  const li = a => '<ul>' + a.map(v => '<li style="margin:4px 0">'+v+'</li>').join('') + '</ul>';
  const acts = ai.actions.map(a =>
    '<li style="margin:4px 0">【'+a.priority+'】'+a.item+'（'+a.owner+'）</li>').join('');

  const html =
    '<div style="font-family:Noto Sans TC,Arial,sans-serif;max-width:720px;color:#222;line-height:1.8">' +
    '<h2 style="border-bottom:3px solid #14664A;padding-bottom:8px">'+period+' 績效分析報告</h2>' +
    '<p style="color:#666;font-size:13px">產製時間：' +
      Utilities.formatDate(new Date(), 'Asia/Taipei', 'yyyy-MM-dd HH:mm') +
    '　受評人數：'+rows.length+' 人　整體平均：'+avg+'</p>' +
    '<h3>一、整體概述</h3><p>'+ai.overview+'</p>' +
    '<p>'+ai.distribution+'</p>' +
    '<h3>二、優勢與風險</h3><p><b>優勢</b></p>'+li(ai.strengths) +
    '<p><b>應關注事項</b></p>'+li(ai.risks) +
    '<h3>三、管理建議</h3><ul>'+acts+'</ul>' +
    '<h3>四、評核明細</h3><table style="border-collapse:collapse;width:100%">' +
    '<tr><th '+thS+'>姓名</th><th '+thS+'>部門</th><th '+thS+
    '>加權總分</th><th '+thS+'>等第</th><th '+thS+'>部門排名</th></tr>' +
    tableRows + '</table>' +
    '<p style="margin-top:24px;padding:12px;background:#f4f4f0;font-size:12px;color:#666">' +
    '本報告由系統自動產製，質性論述係以 AI 輔助生成，僅供管理參考，' +
    '不作為考績評定之直接依據。內容涉及個人資料，請勿轉發。</p></div>';

  MailApp.sendEmail({
    to: to,
    subject: '【績效分析】' + period + ' 分析報告',
    htmlBody: html,
    name: '績效分析自動化系統'
  });
  log_('INFO', '報告已寄送：' + to);
}

/** 主流程：Stage 02 → 03 → 04 → 05 */
function runPipeline() {
  const lock = LockService.getScriptLock();
  if (!lock.tryLock(10000)) { log_('WARN', '另一執行程序進行中，本次略過。'); return; }
  try {
    const rows = buildSummary();      // Stage 02–03
    const ai   = analyze(rows);        // Stage 04
    sendReport(rows, ai);              // Stage 05
    log_('INFO', '流程執行完成。');
  } catch (e) {
    log_('ERROR', e.message);
    notifyAdmin_(e);
    throw e;
  } finally {
    lock.releaseLock();
  }
}

/** 異常通知管理員 */
function notifyAdmin_(e) {
  MailApp.sendEmail(Session.getEffectiveUser().getEmail(),
    '【系統異常】績效分析自動化流程執行失敗',
    '發生時間：' + new Date() + '\n錯誤訊息：' + e.message +
    '\n\n請至「執行紀錄」工作表查看詳情。');
}

/** 安裝觸發器：每月 5 日 09:00 執行（執行一次即可） */
function installTrigger() {
  ScriptApp.getProjectTriggers().forEach(t => ScriptApp.deleteTrigger(t));
  ScriptApp.newTrigger('runPipeline')
    .timeBased().onMonthDay(5).atHour(9).create();
  log_('INFO', '觸發器已建立：每月 5 日 09:00。');
}

APPENDIX A

資訊安全與個人資料保護

績效資料屬《個人資料保護法》所稱之個人資料，且具高度敏感性，蒐集、處理及利用均應符合特定目的且不逾必要範圍。

管控面向應辦事項
告知義務表單說明欄應載明蒐集機關、特定目的、個資類別、利用期間與地區、當事人權利行使方式。
最小蒐集僅蒐集績效評核所必要之欄位，不得蒐集與評核無關之個人資訊。
金鑰保管API 金鑰一律存放於指令碼屬性（Script Properties），嚴禁寫入程式碼或試算表儲存格；人員異動時應即更換。
去識別化送交 Gemini API 之資料須以代碼取代姓名與員工編號，論述回傳後於本地還原。
存取控制試算表與指令碼專案採最小權限原則共用；離職或職務異動人員應於 3 個工作日內移除權限。
傳輸安全全程使用 HTTPS；郵件不得夾帶未加密之原始資料檔案。
保存與銷毀依單位檔案保存年限辦理，屆期由系統管理員刪除試算表與雲端備份，並記錄於「執行紀錄」。
稽核軌跡「執行紀錄」工作表應保留執行時間、層級、訊息與執行者，不得刪除。
禁止事項

不得將完整績效資料（含姓名）貼入任何公開或未經核准之生成式 AI 服務；不得將分析報告轉發予非權責人員；不得以 AI 生成之個人評語作為考績或懲處之唯一依據。
