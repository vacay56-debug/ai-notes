標準作業程序

版　　次1.0

審核週期每季檢視
01

目的

建立以 Claude Code 為核心之個人 AI 代理（AI Agent）系統建置程序，透過「安裝 → 情境 → 記憶 → 技能 → 代理 → 排程」六階段，將重複性行政作業（文件產製、資料彙整、定期報表）轉為可自動執行之工作流，降低人工重工並確保產出品質一致。

本程序不需撰寫程式碼，所有設定均以自然語言提示詞（Prompt）完成，適合行政、政策幕僚及一般知識工作者採用。

02

適用範圍與名詞定義

適用於已具備 Claude Pro／Max 訂閱帳號之使用者，於 macOS、Windows 或 Linux 環境建置個人代理系統。

名詞定義
Claude CodeAnthropic 推出之代理式（Agentic）工作工具，可於終端機、桌面應用程式或 VS Code 中操作，具檔案讀寫、工具呼叫與多步驟任務執行能力。
CLAUDE.md情境設定檔（Onboarding Document）。Claude 於每次對話啟動時自動載入，內含角色定位、語氣、禁用詞、輸出預設等指示，等同「工作交接手冊」。
記憶檔（Memory）以 .md 檔案形式保存之修正紀錄。每次糾正 Claude 後將回饋存檔，避免同一錯誤重複發生。
技能（Skill）可用單一指令（如 /skill-name）觸發之完整工作流，可串接多項外部工具，免除每次重新輸入冗長提示詞。
代理（Agent）各司其職之子任務執行單元，一個代理對應一個檔案、一項職責，可組成分工團隊並設置品質關卡。
例行任務（Routine）雲端排程任務。設定後於 Anthropic 雲端定時自動執行，毋須開啟本機電腦。
MCP（Model Context Protocol）模型情境協定，為 Claude 連接外部服務（Gmail、Google Drive、Notion 等）之標準介面。

六階段採循序建置：前三階段（安裝、情境、記憶）建立「工作基礎」，後三階段（技能、代理、排程）疊加「自動化能力」。首次建置約需 15–30 分鐘，後續依實際使用持續擴充。

05

作業程序

S1

安裝 Claude CodeInstall — 建立基礎環境

目標

完成 Claude Code 安裝並成功登入，此為後續所有步驟之基礎。三種安裝介面擇一即可。

操作步驟

介面適用情境安裝方式
終端機macOS／Linux／WSL，習慣指令列操作者執行 npm install -g @anthropic-ai/claude-code，安裝後輸入 claude 啟動
桌面應用程式一般使用者，偏好圖形介面至 Anthropic 官網下載 Mac／Windows 原生應用程式
VS Code 擴充已使用 VS Code 編輯文件或程式者於擴充功能市集搜尋「Claude Code」安裝，以側邊面板操作
驗證點：啟動後可正常對話，且能讀取指定資料夾內之檔案，即完成本步驟。
S2

建立情境設定檔Context — 撰寫 CLAUDE.md

目標

~/.CLAUDE.md 為 Claude 每次啟動前必讀之「交接手冊」。撰寫一次，每個工作階段自動載入，免除每次重新交代背景。

設定檔應涵蓋之四要素

要素說明與範例
角色（Role）你的職務、業務範圍與 Claude 應扮演之角色。例：「我是中央機關政策幕僚，你是我的文書與研析助理。」
語氣（Voice）輸出風格要求。例：「一律繁體中文（臺灣用語）、結論先行、極簡直接、表格優先。」
禁用詞（Banned words）禁止出現之詞彙或句式。例：AI 腔填充語（「值得注意的是」「總而言之」）、簡體用語。
預設值（Defaults）未特別指定時之預設行為。例：公文採三段式（主旨／說明／辦法）、英文術語首次出現採「中文（英文全稱，縮寫）」格式。

提示詞（貼上即用）

PROMPT 
幫我從零建立我的 CLAUDE.md 情境設定檔。請逐項詢問我：
（1）我的職務角色與業務範圍
（2）輸出語氣與文風要求
（3）禁用詞與禁止句式
（4）輸出格式預設值（語言、結構、術語格式）
（5）我希望你如何與我協作
彙整後將最終檔案存至 ~/.CLAUDE.md。
驗證點：開啟新對話後直接指派任務，若 Claude 未經提醒即符合設定之語言、文風與格式，即代表設定檔生效。
S3

建立記憶機制Memory — 讓同一錯誤不再發生

目標

將每一次對 Claude 的糾正轉為獨立 .md 記憶檔，下次工作階段自動載入。累積愈久，代理愈貼合個人工作習慣。

運作邏輯

  1. 使用者於對話中糾正 Claude（例：「公文說明段落每項以句號結尾，不用分號」）。
  2. Claude 將該回饋存為記憶檔，置於 ~/.claude/projects/[專案名]/memory/。
  3. 檔名依性質加上前綴：feedback_（修正回饋）、user_（個人偏好）、project_（專案脈絡）、reference_（參考規範）。
  4. 所有記憶檔統一登錄於 MEMORY.md 索引，下次啟動時載入。

提示詞（貼上即用）

PROMPT 
從現在起，每當我糾正你，就將該回饋存成獨立的 .md 檔，
路徑為 ~/.claude/projects/[專案名]/memory/。
檔名依性質加上前綴：feedback_、user_、project_ 或 reference_。
所有記憶檔統一登錄於 MEMORY.md 索引，供下次工作階段載入。
驗證點：糾正一項格式錯誤後開啟新對話，指派同類任務，確認 Claude 已自動套用修正。
維護要點：記憶檔建議每月盤點一次，合併重複項目、刪除過時規則，避免記憶膨脹造成指示互相衝突。
S4

建立技能Skills — 一鍵觸發完整工作流

目標

將重複執行之多步驟工作流封裝為技能，之後於任何對話輸入 /技能名稱 即可觸發，免除每次重打兩百字提示詞。技能可串接 MCP 連接器（Gmail、Google Drive、Notion 等）跨工具執行。

操作步驟

  1. 選定一項每週重複兩次以上之工作流（例：會議紀錄整理、週報彙整、輿情摘要）。
  2. 明確定義三件事：觸發條件（何時執行）、輸入（來源檔案或資料）、輸出（格式與交付位置）。
  3. 以下列提示詞請 Claude 建立 SKILL.md 並接上所需連接器。
  4. 實測執行一次，依結果修正 SKILL.md 內容。

提示詞（貼上即用）

PROMPT 
把以下工作流封裝成一個 /（名稱）技能：
【描述觸發條件、輸入、輸出】。
請建立 ~/.claude/skills/（名稱）/SKILL.md，
接上我需要的 MCP 連接器（Notion、Gmail、Drive 等），
並讓我能在任何對話中以斜線指令觸發。

行政應用範例

技能名稱觸發 → 輸入 → 輸出
/meeting-minutes會後執行 → 錄音逐字稿 → 三段式會議紀錄（結論、決議、待辦分工）
/weekly-report每週五 → 本週工作紀錄資料夾 → 週報表格＋下週預定事項
/doc-review收到文件 → Word／PDF 草案 → 多角色審查意見表（法制、預算、業務視角）
驗證點：於全新對話輸入 /技能名稱，確認工作流完整執行且輸出符合定義格式。
S5

建立代理團隊Agents — 分工協作與品質關卡

目標

將複雜流程拆解為多個專責代理：一個代理、一個檔案、一項職責。並依任務性質配置模型——分析規劃類交由高階模型（如 Opus）、執行產出類交由中階模型（如 Sonnet），兼顧品質與成本。

建議團隊結構

角色建議模型職責
策略分析代理Opus需求解析、架構規劃、關鍵決策建議
執行產出代理Sonnet依規劃產出文件、表格、簡報等交付物
品質關卡（QA Gate）—設定 95／100 品質門檻，低於門檻之產出自動退回重做

提示詞（貼上即用）

PROMPT 
幫我為【流程名稱】建立一個代理團隊。
每位專責代理建立一個 .md 檔，路徑為 ~/.claude/agents/。
分析規劃類角色使用 Opus，執行產出類角色使用 Sonnet。
加入一道 95/100 的品質關卡（QA Gate），
任何低於門檻的產出一律退回重做。
驗證點：指派一項完整任務，確認各代理依職責分工執行，且品質關卡確實攔截未達標之產出。
設計原則：代理數量寧少勿多。先以「分析＋執行＋品管」三角結構起步，確認穩定後再逐步擴充，避免流程過度複雜難以除錯。
S6

設定例行任務Routines — 雲端排程自動執行

目標

將已驗證穩定之代理或技能設為雲端例行任務（Routine），如同雲端排程器（Cron Job）：設定一次即定時自動執行，毋須開啟本機電腦，產出自動投遞至指定位置。

操作步驟

  1. 確認欲排程之代理或技能已在手動模式下穩定執行至少三次。
  2. 決定排程頻率（每日、每週特定日、每月）與執行時間。
  3. 指定輸出投遞位置：資料夾、Notion 頁面、電子郵件或其他工具。
  4. 以下列提示詞建立例行任務，並於首次自動執行後檢核產出。

提示詞（貼上即用）

PROMPT 
建立一個 Claude 例行任務（Routine），
依【排程頻率】自動執行我的【代理或技能名稱】。
請在 Anthropic 雲端執行，不依賴我的本機電腦。
產出自動投遞至【資料夾／Notion 頁面／指定工具】。

排程範例

排程任務內容
每日 08:00彙整前一日重點信件與行事曆，產出當日晨報
每週一 09:00彙整上週工作紀錄，產出週報投遞至 Notion
每月 1 日彙整當月預算執行數，產出經費控管摘要表
驗證點：首次排程執行後，於預定時間確認產出已出現在指定位置且內容正確。前兩週建議每次執行後人工抽核。
06

注意事項

  • 循序建置：六步驟具相依性，勿跳過情境（S2）與記憶（S3）直接建立代理，否則產出品質不穩定且難以除錯。
  • 小步快跑：每項技能與代理先手動驗證穩定，再納入自動排程；未經驗證之流程不得直接上線自動執行。
  • 人工把關：自動化產出屬「草稿」性質，正式對外文件仍應經人工審閱定稿，責任歸屬不因自動化而移轉。
  • 資料分級：涉及機密、敏感公務資訊或個人資料者，禁止置入雲端代理工作流；連接外部服務前應確認符合機關資安規範。
  • 成本管理：高階模型（Opus）保留予分析決策類任務，例行產出使用中階模型（Sonnet），定期檢視用量。
07

維運與版本管理

週期維運項目
每週抽核例行任務產出品質；記錄異常案例供修正。
每月盤點記憶檔：合併重複、刪除過時規則；檢視技能使用頻率，停用閒置技能。
每季全面檢視 CLAUDE.md 是否仍符合現行業務；更新本 SOP 版次並留存修訂紀錄。
