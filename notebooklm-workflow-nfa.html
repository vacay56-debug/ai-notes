NotebookLM 怎麼接進救護科的工作流

科內業務的共同型態是：法規要查得準、公文要出得快、專案要盯得住。以下是把文件轉為可引用知識、再轉為公文產出的六階段流程，含每階段的檢核點與不可跨越的資安紅線。

S1資料治理法規與案卷盤點 S2知識治理建立法規知識庫 S3知識應用科內五類場景 S4文書產製簽稿、預算、簡報 S5流程治理陳核與列管 S6自動化提醒與跨系統

資安紅線：先確認，再上傳

  • 國家機密與密等公文（機密、密、極機密）
  • 傷病患姓名、身分證號、病歷與到院前紀錄
  • 未決標之採購底價、評選委員名單
  • 人事考評、申訴與調查案卷
  • 已公布之法規、函釋、公開標案文件
  • 去識別化後之統計數據與教材
S1治理

資料治理：先讓法規與案卷乾淨可用

目標是把散在個人電腦、共用磁碟與公文系統的檔案，收斂成一套有版本、有密等、有維護人的文件集。法規版本錯誤會直接導致公文引據錯誤，這一步不能省。

Input

  • 《緊急醫療救護法》及施行細則
  • 《救護技術員管理辦法》
  • 歷年函釋、解釋令與會議決議
  • 各直轄市、縣（市）消防局來文
  • TECC／PCC／CIT 教材與師資名冊
  • 預算書、招標文件、出國考察報告

Action

  • 逐份標註密等，密件一律排除
  • 法規以最新修正公布日期版本為準
  • 移除個資與可識別之傷病患資料
  • 刪除舊版與重複檔，統一命名
  • 指定每一主題之維護承辦人

Output

  • 可上傳文件清單與不可上傳清單
  • 單一版本之法規與教材文件集
  • 維護分工與更新頻率表
GATE 01

任抽 10 份文件，均能立即回答「密等為何、是否最新版、誰維護」。有一份答不出來就不要進入 S2。

S2知識

知識治理：建立可回溯條次的法規知識庫

依業務屬性切分筆記本，不要全部塞在一起。NotebookLM 的關鍵價值在於答案可回溯到條次與頁碼，這是它能作為公文引據來源的前提。

Input

  • S1 產出之可上傳文件集
  • 主題切分原則（依業務別）

Action

  • 建立五本主題筆記本：法規、訓練體系、預算與採購、國際交流、專案管理
  • 檢視 AI 摘要，確認未曲解法條文義
  • 以實際函詢問題測試問答
  • 逐題驗證引用是否指向正確條次

Output

  • 可查詢、可引用之主題知識庫
  • 常見函詢問題與標準答復
  • 新進承辦人自學入口
GATE 02

以 20 題實際法規問題測試，答案正確且引用條次可核對者須達八成以上。未達標即補件或重切主題。

S3應用

知識應用：科內五類優先落地場景

先挑一項業務試點，做出可展示的成果，再橫向推廣至組內其他科。下列五類回收最快。

01

法規查詢

回答同時附上條次與函釋出處，可直接引為簽稿依據。

「中級救護技術員（EMT-2）得執行之救護項目有哪些？依據為何？」
科內承辦 · 地方消防局諮詢
02

作業程序

把辦法條文拆成可執行的辦理步驟與應備文件。

「救護技術員證照展延資格不符，應如何處理？」→ 查核時數、通知補正、審查、函復
證照管理 · 訓練業務
03

專案管理

將計畫書、預算表、會議紀錄放進同一筆記本，掌握全案進度。

「CIT 國際研討會目前有哪些未決事項？經費尚有多少可用？」
研討會 · 出國考察 · 採購案
04

會議整理

跨機關協調會議錄音轉文字後，自動抽出決議與主協辦分工。

決議事項／辦理期限／主辦機關／列管與否
衛福部 · 國防部 · 22 縣市
05

教育訓練

TECC、PCC、CIT 教材與師資制度的隨問隨答，縮短接手業務的學習期。

「TECC 師資認證的資格條件與換證週期為何？」
新進承辦 · 種子教官 · 地方訓練單位
GATE 03

試點承辦人在無人督促下持續使用滿一個月，且至少一件公文實際引用其查得之依據，才算落地。

S4產製

文書產製：把答案寫成可陳核的文件

NotebookLM 負責查得準，通用模型負責寫得好。查詢留在知識庫，撰寫交由 Claude、Gemini 或 ChatGPT，並依三段式架構產出。

Input

  • 知識庫查得之法條與函釋
  • 公文格式範本與行文慣例
  • 預算與採購既有文件格式

Action

  • 依主旨／說明／辦法產出簽稿初稿
  • 比對初稿引據與原文，剔除臆測內容
  • 人工複核法條字號、日期、金額
  • 依機關用字慣例調整（臺、爰、爰此）

Output

  • 簽、函、書函初稿
  • 預算說明書與績效指標
  • 招標規格書與評選基準
  • 政策簡報與出國報告
GATE 04

法條字號、公布日期、預算金額、機關全銜須 100% 人工複核，不得直接採信生成內容。

S5流程

流程治理：陳核路徑與案件列管

文稿產出只是半套。把陳核層級、辦理期限與列管節點固定下來，人只在需要判斷的節點介入。

Input

  • S4 之定稿文件
  • 分層負責明細表
  • 來文限辦日期

Action

  • 依承辦、科長、組長、署長設定節點
  • 設定限辦前提醒與逾期警示
  • 保留人工審核關卡，不全自動決行
  • 建立專案列管清單與辦理情形回報

Output

  • 可追溯之標準辦理流程
  • 逾期預警與催辦通知
  • 各案件耗時與瓶頸統計
GATE 05

任一案件均能回答「現在停留在哪一層、已滯留幾日、距限辦日剩幾日」。

S6自動

自動化：先停在提醒層級，再談跨系統

公務系統介接涉及資安規範與權責，導入應審慎分段。建議先做通知與提醒，不做代為決行；跨系統寫入須另案評估。

Input

  • 已驗證之知識庫（S2）
  • 已標準化之流程（S5）
  • 資通安全責任等級規範

Action

  • 第一階段：限辦提醒、會議行事曆同步
  • 第二階段：預算執行率與採購時程追蹤
  • 界定不得由系統自動執行之事項
  • 全程留存執行紀錄供稽核

Output

  • 例行性提醒自動化
  • 人力回到政策判斷與跨機關協調
  • 可持續累積之科務知識資產
GATE 06

每一自動化動作均可查出「依據哪份文件、依哪條規定、經誰核准」。無法回答者不得上線。

密等分級先於一切

結論

NotebookLM 是科務知識管理的第一步，不是最後一步。它讓法規與案卷變成可引用的答案；要讓答案變成行政效能，還需要接上文書產製、陳核治理與例行自動化。

六階段依序完成、每個檢核點確實通過，並守住資安紅線，才能在合規前提下，把時間還給政策研判與跨機關協調。
