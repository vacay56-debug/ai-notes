先搞懂 · What is Claude Code

它不是聊天機器人，是「會動手的程式代理」

Claude Code 是 Anthropic 推出的終端機原生 AI 程式設計代理（terminal-native coding agent）。它跟你平常用的瀏覽器版 Claude（claude.ai）最大的差異是：它直接在你電腦的終端機裡執行，能讀取整個專案資料夾、直接建立與修改檔案、執行指令，而不只是回覆文字。你可以把它想成一位坐在你終端機裡的資深工程師。

與你先前用「單檔 HTML 工具（如 ROSC 模擬器）」的經驗相比，這是從「一個檔案」升級到「一整個專案」的工作方式——這正是為什麼需要一套流程來駕馭它。

貫穿範例 · The Running Example

我們要一起打造：「EMT 換證與繼續教育資訊網」

為了讓 7 個步驟不只是抽象概念，以下每一步都會套用同一個範例——一個對外的公開資訊網站，讓全國救護技術員（Emergency Medical Technician, EMT）查詢換證規定、繼續教育課程與時數。這個情境貼近你的實際業務，也方便把政策規劃的思維直接對映到網站建置流程。

對象：EMT-1 / EMT-2 / EMT-P 目標：自助查詢、降低洽詢話務 性質：政府對外資訊網
1STEP

從明確目標開始 Start With a Clear Goal

明確的目標，會引導後續每一個決策

在寫任何一行程式之前，先把「這個網站要達成什麼」想清楚。目標模糊，AI 的產出就會發散——因為 AI 不會、也不該替你決定業務目標。

先回答這四個問句

PROJECT GOAL · 四問句 × 範例
關鍵問句範例：EMT 換證資訊網
這個業務在做什麼？提供全國 EMT 換證規定與繼續教育課程資訊
網站給誰用？全國 EMT、各縣市消防局承辦人
主要目標是什麼？讓 EMT 自助查詢換證期限與時數，降低電話洽詢量
希望訪客做什麼（CTA）？「查詢我的換證期限」／「報名繼續教育課程」
2STEP

撰寫詳細需求簡報 Create a Detailed Brief

上下文越完整，來回修改越少

把步驟 1 的目標展開成一份「需求簡報（brief）」交給 Claude Code。這份 brief 就是你給工程師的委辦說明——內容越具體，重工越少。

一份 brief 要涵蓋六件事

PROJECT BRIEF · 範例內容
項目範例內容
業務概述消防署救護科提供之 EMT 換證與繼續教育查詢服務
目標對象EMT-1／EMT-2／EMT-P，年齡與數位程度不一，需高易讀性
品牌調性專業、可信、政府識別；沉穩不花俏
需要的頁面首頁、換證規定、課程查詢、時數說明、常見問答
關鍵功能時數計算、課程篩選（分級／地區）、期限提醒
主要 CTA查詢換證期限、報名課程

進階技巧：把這份 brief（連同你的繁中／公文格式偏好）寫成一個 CLAUDE.md 檔案放在專案根目錄。Claude Code 每次啟動都會自動讀取它，等於一次設定、每次生效。官方建議控制在 200 行以內，並讓每條指令「可驗證」。

3STEP

提供參考網站 Share Reference Websites

給方向，而不是讓 AI 用猜的

文字很難描述「好看」。與其反覆用形容詞，不如直接給幾個參考網站，並指出你要它學哪些面向。這能大幅減少視覺上的來回。

從六個維度指定方向

版面 Layout字體 Typography色彩 Colors 間距 Spacing導覽 Navigation動效 Animations
對 Claude Code 下的指示（範例）
參考 gov.uk 與 NHS 111 的資訊架構：
・版面要乾淨、單欄為主、大字級
・色彩沿用政府識別色，文字對比需符合無障礙 (WCAG AA)
・導覽固定在頂部，不要輪播與花俏動畫
・字體以易讀的無襯線為主
4STEP

動手前先規劃 Plan Before You Build

規劃勝過除錯

在開始寫程式前，先定好架構與技術棧。善用 Claude Code 的計畫模式（Plan Mode）——它會先提出一份實作計畫，你確認（或要求修改）後才動工，就像正式施工前先審圖。

要先規劃的六件事

  • 網站架構（site architecture）
  • 頁面層級（page hierarchy）
  • 導覽結構（navigation）
  • 元件清單（component list）
  • 技術棧（tech stack）
  • 實作路線圖（implementation roadmap）

技術棧：原圖建議 vs. 依需求調整

TECH STACK
層面原圖建議本範例的務實選擇
框架Next.js純資訊網若無登入，靜態頁即可
樣式Tailwind CSS可沿用
語言TypeScript可沿用
資料庫PostgreSQL若不需帳號系統可省略

重點：技術棧要服務目標，不是越多越好。像這種對外靜態資訊網，用輕量方案 + GitHub Pages（你已熟悉）反而更好維護。

5STEP

建置、測試、改進 Build, Test & Improve

小步快跑，逐次迭代

不要一次要它「把整個網站做完」。改成一頁一頁、一個功能一個功能地做，每做完一段就在瀏覽器實際檢視，再繼續下一段。這樣出錯時範圍小、好回頭。

6STEP

專業地部署 Deploy Like a Professional

上線，收集回饋，再改進

上線不是終點。部署前逐項檢查，上線後蒐集使用者回饋，再滾動修正。

上線前檢查清單

  • 行動裝置響應（手機 / 平板正常顯示）
  • 頁面速度（用 Lighthouse 檢測，目標 90 分以上）
  • 表單可正常送出
  • 沒有失連連結（broken links）
  • SEO metadata（標題、描述完整）
  • 無障礙（鍵盤操作、對比、替代文字）
  • 內容正確性（法規時數、日期無誤）

範例：可請 Claude Code 直接產出可部署的靜態檔，推送到 GitHub Pages（你先前已操作過），或交付機關內部主機。

7STEP

最重要的一課 The Biggest Lesson

Claude 寫程式，你提供願景

回頭看，網站做得好不好，關鍵幾乎不在「AI 會不會寫程式」，而在你有沒有把前面幾步做扎實：明確目標、詳細需求、參考設計、穩固架構、迭代改進。

給你的學習路徑 · Learning Path

從你現在的位置，5 步接軌 Claude Code

  • 用既有經驗當起點：你已會做單檔 HTML 工具，觀念上只差「多檔專案管理」。
  • 先拿小專案練手：例如把現有的 ROSC 模擬器搬進 Claude Code 做一次小重構，感受它讀取整個資料夾的能力。
  • 建立 CLAUDE.md：把繁中（臺灣用語）、公文三段式、術語格式等偏好寫進去，讓它每次都遵守。
  • 練習 Plan Mode：任何較大任務都先讓它出計畫、你審過再執行。
  • 部署到 GitHub Pages：把成品上線，完成一次完整循環。
誠實提醒 · Common Pitfalls

三個值得先知道的注意事項

需求模糊會空轉

面對不清楚的任務，代理容易反覆嘗試或自行「腦補」需求。步驟 1–2 做扎實，是省時的關鍵。

它能存取你的檔案系統

Claude Code 會直接改真實檔案。重要或不可逆的動作，務必逐項確認再放行；敏感專案先確認機關的 AI 使用規範。

用量有滾動上限

訂閱額度以數小時為單位滾動計算，且與 claude.ai 共用。上午聊很多，下午的 Claude Code 額度會相應變少。

技術棧不是越多越好

原圖的 Next.js＋資料庫適合有登入的動態網站；純資訊網用輕量方案更省維護成本。

「Claude 寫程式，你提供願景。」

把政策規劃的嚴謹，用在提需求上——這就是用好 Claude Code 的全部祕訣。
