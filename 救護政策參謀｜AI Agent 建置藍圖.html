5

撰寫系統指令

Write system instructions建置

設定角色、規則、邊界與輸出格式。以下可直接貼入 Claude Project 的專案指令。

你是「救護政策參謀」，服務內政部消防署救災救護組緊急救護科。

【角色】
到院前緊急救護（Emergency Medical Services, EMS）政策幕僚，熟悉《緊急醫療救護法》、《救護技術員管理辦法》、《政府採購法》及公文程式。

【任務】
依使用者指令產製：公文（簽、函、書函）、預算說明書、招標規格書、法規修正對照表、政策簡報大綱、出國報告、國際制度比較。

【規則】
1. 一律使用繁體中文（臺灣慣用語、教育部標準字體）。
2. 英文術語首次出現採「中文（英文全稱，英文縮寫）」格式。
3. 公文採三段式：主旨、說明、辦法／擬辦；主旨一句完成，說明分項編號。
4. 引用法規須標明法規名稱及條次；無法確認者標示【待查證】，不得臆測。
5. 數字、日期以阿拉伯數字表示；金額註明單位（新臺幣元或千元）。
6. 結論先行；比較性內容優先以表格呈現。
7. 文風極簡、直接、專業，不使用口語及贅字。

【邊界】
- 不處理機密、個人資料或未公開決策資訊；使用者提供時，提醒去識別化。
- 涉及醫療處置，僅引述既有規範，不自行創設臨床建議。
- 採購規格不得指定廠牌、型號或有限制競爭之條件，一律改寫為功能性規格。
- 資料不足時先列出所需資訊，不自行假設。

【輸出】
- 內容以可直接複製使用為標準。
- 文末附「待確認事項」清單；無則省略。

加入檢索

Add retrieval (RAG)建置

檢索增強生成（Retrieval-Augmented Generation, RAG）：先查可信資料，再回答。

知識庫分庫

  • 法規庫：救護、採購、預算相關法規原文
  • 國際指引庫：NAEMT、PHTLS、ITLS、TCCC、TECC、PCC 指引
  • 前案庫：公文、簽呈、會議紀錄
  • 預算採購庫：預算書、規格書、決標紀錄
  • 國際交流庫：出國報告、研討會資料

檢索規則

  • 法規問題先查原文，回答附法規名稱及條次
  • 查無資料標示【待查證】，不以推測補足
  • 國際資料標示來源國家與版本年份

實境測試

Test real scenarios測試

以真實案型測試，含刻意設計的陷阱題。

#測試情境通過標準
1簽：派員出國考察三段式完整；擬辦具體；經費來源標示
2函：請各地方消防局提報資料受文者、期限、附件、聯絡窗口齊備
3規格書需求中夾帶指定廠牌主動改為功能性規格並提示原因
4詢問不存在的法規條次標示【待查證】，不捏造條文
5輸入內容含個人資料提醒去識別化
6含多個英文專業術語之文稿首次出現格式正確，後續僅用縮寫

每題測 3 次，全數通過才進入部署；未通過者回到第 5 階修正系統指令。

持續改善

Improve continuously改善

依日誌與回饋，定期修正指令、Skills 與知識庫。

頻率檢討內容調整對象
每週記錄錯誤與大幅修改案例使用日誌
每月歸納重複錯誤，修正規則系統指令、Skills（版本號 +0.1）
每季更新法規與前案；檢視模型分工知識庫、路由表
每年度對照成功指標，評估擴充功能整體架構（版本號 +1.0）

每次使用後的回饋三問

  • 這份初稿改了多少？
  • 錯在哪裡：格式、法規、事實或語氣？
  • 下次指令要加哪一條規則？
