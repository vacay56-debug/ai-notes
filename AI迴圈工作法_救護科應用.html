AI 迴圈工作法
讓代理人在你休息時完成任務

Loop Engineering（迴圈工程）不是新工具，而是一種設計方式：把「你每一步下指令」的工作，改造成「自己執行、自己驗證、自己決定何時停止」的迴圈——概念上很接近勤務中心的排班表，一旦設定完成，就依表運作。

Claude Code 創建者 Boris Cherny 描述的轉變，可以濃縮成一句話：使用者的角色不再是「逐步下指令」，而是「同時經營多個自行運作的迴圈」。 — 摘要自 Claude Code 團隊訪談，非逐字引述

迴圈生命週期 ｜ 對照 24 小時勤務時間軸

設定目標與停止條件
執行代理自動運作
驗證每輪自動檢查
回報條件達成即停止
你在班：設定與交接迴圈值班：無人值守運作
壹

核心差異：對話模式 vs 迴圈模式

兩者的差別不在「AI 變聰明」，而在於誰負責推進流程。對話模式下，每一次修正都要你重新輸入；迴圈模式下，「什麼時候算完成」被明文寫進設定裡，推進的責任交給系統本身。

傳統對話模式

  1. 你下達提示
  2. Claude 回應
  3. 你檢查、你修改
  4. 重複，直到你滿意為止

迴圈模式

  1. 你設定目標與停止條件
  2. Claude 自動執行一輪
  3. 系統自動驗證是否達標
  4. 未達標則自動接續下一輪

1

觸發器（Trigger）/loop · routines

/loop 在單一工作階段內依時間間隔重複執行，最長運作 7 天，工作階段結束即停止；若需要不受本機開關限制、可長期常駐或由外部事件（例如 GitHub 事件、API 呼叫）觸發，則要用 routines——在 Anthropic 雲端基礎架構上運作的排程機制。

2

執行者（Execution）代理迴圈

每一輪都是「取得脈絡 → 採取行動 → 驗證結果」的循環：Claude 讀取現有狀態、呼叫工具（讀寫檔案、執行指令、網路搜尋等），再依結果決定下一步，這個循環稱為代理迴圈（agentic loop）。

3

驗證者（Verifier）/goal

/goal 讓你寫下一個可驗證的完成條件（例如「所有測試通過」）。每一輪結束後，一個較小的模型（預設為 Haiku）會依對話紀錄判斷條件是否成立；未成立就附上理由，自動進行下一輪。

4

停止規則（Stop Rules）condition

/goal 的完成條件本身就是停止線，也可附加回合數或時間上限（如「20 回合後停止」）；/loop 的定期任務則以 7 天為運作上限，逾時或按 Esc 即結束。

5

記憶體（Memory）CLAUDE.md

CLAUDE.md 是專案根目錄下的一份說明文件，每次工作階段啟動時自動載入，用來記錄規範、慣例與決策依據；Claude Code 另外也會在工作過程中自動累積經驗記憶。

6

技能（Skills）已具備

可重複使用的工作流程包，以指令形式呼叫。這個概念與您已經建置的 8 個 nfa- 開頭客製 Skills（nfa-gongwen、nfa-ems-research 等）在架構上完全一致——知識層已經到位。

參

重要釐清：這些功能現在能用嗎？

/loop、/goal、routines 屬於 Claude Code——一個獨立於 Claude.ai 聊天介面的產品，以終端機、桌面應用程式的「Code」分頁或瀏覽器版執行。您目前在 Claude 桌面版使用的「Customize → Skills」上傳功能，屬於 Claude.ai／桌面應用程式的知識層，兩者是不同的產品介面。

功能所屬產品您目前狀態
自訂 Skills（SKILL.md）Claude.ai 桌面版已建置 8 個
Google Drive／Gmail／Calendar MCPClaude.ai 桌面版已連接
/loop（單一工作階段內定期執行）Claude Code需另外啟用
/goal（自動驗證並持續推進）Claude Code（v2.1.139 以上）需另外啟用
routines（雲端常駐排程／事件觸發）Claude Code需另外啟用

好消息是：SKILL.md 檔案格式在兩個產品之間共通，您既有的知識層可以直接沿用，不需要重做。

應用到救護科工作的三個情境

以下依「觸發、執行、驗證、停止規則、記憶」五個欄位，示範如何把既有的三個 Skill 改寫成迴圈設計；即使暫不啟用 Claude Code，這套思考方式也能套用在目前逐輪手動操作上——重點是把「什麼時候算完成」講清楚。

A

國際 EMS 政策監測迴圈

觸發
每週一次（/loop 或 routines 排程）
執行
呼叫 nfa-ems-research，檢索美、日、澳最新 TECC／PCC 政策發布與修法動態
驗證
是否出現「上次監測未曾記錄」的新文件
停止規則
連續兩次無新資料即暫停，或達 10 次迭代上限
記憶
每次寫入監測紀錄檔，並依既有負面表列排除 CIT 內容（屬警政署／衛福部業務）

簡報／出國報告迭代產製

成本控管提醒：迴圈會持續消耗 token 與運算成本，性質上如同勤務預算控管——啟用前務必比照經費控管的習慣，設定明確的迭代上限與停止條件，避免無止盡運作。持續性、沒有明確終點的任務（如情境 A 的監測工作），較適合用 /loop 或 routines，而不是 /goal——因為 /goal 假設任務有明確終點，用在無終點任務上容易空轉。
