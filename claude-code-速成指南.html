核心概念（白話說明）

Claude Code 是一個在終端機（PowerShell）裡工作的 AI 助理：你用中文描述任務，它直接讀取、修改、建立你電腦裡的檔案，不需要你複製貼上。它與網頁版 Claude 最大的差別是「動手」——網頁版產生內容給你搬運，Claude Code 直接在資料夾裡完成工作。它每次要動檔案前都會先徵求你的同意，這個「先問再做」機制就是它的安全底線。對文書工作者而言，它的本質是：一位能一次處理 50 份檔案、且聽得懂公文格式的數位科員。

貳

80/20 關鍵（最重要的 20%）

關鍵技能為什麼是槓桿點可量化指標
1. 專用資料夾工作法 永遠在一個專屬資料夾（如 C:\claude-work）內啟動 claude。範圍清楚＝安全、快、不誤傷其他檔案。 每次任務都在專用資料夾內完成
2. 用中文下明確指令 不用學指令語法，關鍵是像交辦業務一樣說清楚：「做什麼、對哪些檔案、輸出成什麼格式」。 一次指令完成率 ≥ 70%
3. CLAUDE.md 常設指示 把「一律繁體中文、公文三段式、臺灣用語」寫進 CLAUDE.md，每次開啟自動生效，不必重複交代。 建立 1 份個人化 CLAUDE.md
4. 批次處理思維 單份文件用網頁版就好；Claude Code 的價值在「一個指令處理一整個資料夾」——改格式、抽摘要、統一用語。 完成 1 次 10 份以上批次任務
5. 權限審核習慣 看懂它每次「請求許可」的內容再按同意；重要原始檔先備份。這是唯一必須養成的紀律。 0 次誤刪、誤改原始檔
6. /init 與斜線指令 進入後輸入 /init 自動產生 CLAUDE.md 草稿；/help 看功能、/resume 接續上次對話。三個指令就夠用。 熟用 3 個斜線指令
參

7 天速成計畫

第 1 天｜安裝與第一次啟動

預估 45–60 分鐘｜成果：成功啟動 claude 並完成登入
  1. 開啟 PowerShell（建議以系統管理員身分），執行官方原生安裝：
# Windows PowerShell 原生安裝（免 Node.js）
irm https://claude.ai/install.ps1 | iex

# 關閉並重開終端機後驗證
claude --version
claude doctor   # 自動診斷安裝與設定狀態
  • 建議加裝 Git for Windows（git-scm.com），讓 Claude Code 使用功能較完整的 Bash 工具。
  • 建立專用資料夾 C:\claude-work，進入後輸入 claude，依畫面提示用瀏覽器登入帳號（需 Pro 以上訂閱或 Console 帳號）。

第 2 天｜認識「先問再做」與基本對話

預估 30–45 分鐘｜成果：完成第一次「請它建檔、改檔」的完整循環
  • 在專用資料夾放 2–3 份不重要的 Word 或文字檔，請它「列出這個資料夾有哪些檔案並各用一句話說明內容」。
  • 請它「建立一份 test.md，內容是本科三項業務職掌」，觀察它如何請求許可、你如何核准。

第 3 天｜建立你的 CLAUDE.md

預估 45 分鐘｜成果：一份個人化常設指示檔
  • 在資料夾內輸入 /init 產生草稿，再請它加入你的規則：一律繁體中文（臺灣用語）、公文三段式（主旨／說明／辦法）、英文術語首次出現採「中文（英文全稱，縮寫）」格式。
  • 測試：請它寫一段任意說明文字，確認規則自動生效。

第 4 天｜第一次批次處理

預估 60 分鐘｜成果：一個指令處理 5 份以上檔案
  • 放入 5–10 份非機敏的舊文件（去識別化練習稿即可），下指令：「閱讀資料夾內全部檔案，各產出 100 字摘要，彙整成一份 summary.md」。
  • 再試進階版：「把所有檔案中的『緊急救護技術員』統一為『救護技術員（Emergency Medical Technician, EMT）』」。

第 5 天｜格式轉換與文件產製

預估 60 分鐘｜成果：從雜亂素材產出一份格式正確的文件
  • 把一份會議逐字稿或雜記丟進資料夾，請它「整理成會議紀錄：時間、出席、決議事項、待辦分工」。
  • 練習「多檔合一」：把 3 份分散的補充資料整併成單一份報告草稿。

第 6 天｜修正與迭代能力

預估 45 分鐘｜成果：學會用追問把 70 分成品改到 90 分
  • 針對第 5 天的產出連續下 3 輪修正指令：「第二段太冗，壓縮到一半」「補上法規依據段」「語氣改為對上級陳報」。
  • 練習 /resume：關掉終端機後重開，接續昨天的工作脈絡。

第 7 天｜完成第一個小專案

預估 60–90 分鐘｜成果：一套可重複使用的「個人文書工作流」
  • 綜合演練：建立 C:\claude-work\週報 資料夾，放入本週素材，一個指令產出「本週業務週報」草稿。
  • 把成功的指令句寫進 CLAUDE.md 或另存為「指令範本.md」，之後每週重複使用——這就是你的第一個自動化資產。

三個實作練習（由淺入深）

練習一（淺）｜資料夾整理員

工具：PowerShell＋Claude Code｜預估 30 分鐘

目標：體驗「AI 直接操作檔案」的核心價值。

  • 準備一個混雜 15–20 份檔案的資料夾（簡報、公文稿、照片皆可）。
  • 指令重點：「依檔案性質建立子資料夾分類歸檔，並產出一份 index.md 清單，註明每份檔案的主題與日期」。
  • 成功標準：分類正確率你能接受、清單可直接當卷宗目錄用。

練習二（中）｜批次摘要與用語統一

工具：Claude Code＋10 份去識別化文件｜預估 60 分鐘

目標：建立「一對多」批次處理能力。

  • 放入 10 份文件（如歷年計畫書節錄、研習講義）。
  • 步驟重點：先請它「掃描全部檔案，列出用語不一致之處」→ 核可後「統一修正並逐檔記錄修改處」→ 最後「產出總表：檔名、主旨、關鍵修改」。
  • 成功標準：修改紀錄可追溯，總表可直接貼進簽稿附件。

練習三（深・可展示作品）｜EMS 政策知識庫

工具：Claude Code＋主題文件 20 份以上｜預估 2–3 小時（可分次）

目標：產出一份可對外展示、可持續維護的成果。

  • 蒐集單一主題（例如 TECC 訓練體系）的公開資料：法規條文、課程綱要、國際文獻摘要、歷次會議結論。
  • 請 Claude Code 建立知識庫結構：01-法規依據／02-課程與師資／03-國際比較／04-推動歷程，逐區產出彙整文件，最後生成一份 HTML 總覽頁（含目錄、各節摘要、資料清單）。
  • 成功標準：同仁打開 HTML 頁 3 分鐘內能掌握該政策全貌——這就是可放進業務交接或簡報的「作品」。

常見錯誤與避免方法

常見錯誤修正方法
1. 在桌面或整顆 C 槽啟動——範圍太大，又慢又危險。永遠 cd 進專用工作資料夾再輸入 claude；一個專案一個資料夾。
2. 指令太模糊——「幫我整理一下」讓 AI 只能猜。套公式：「對【哪些檔案】做【什麼動作】，輸出成【什麼格式】」。像寫辦法段一樣具體。
3. 不看許可內容就全部同意——等於放棄唯一的安全閥。批次任務前先備份原始檔；許可視窗至少確認「它要動哪個檔、做什麼事」。
4. 安裝後找不到 claude 指令——PATH 未生效是 Windows 最常見卡關。先重開終端機；仍失敗則執行 claude doctor，或依提示把 %USERPROFILE%\.local\bin 加入使用者 PATH。
5. 把機敏公文直接餵入練習——學習期風險不必要。練習一律用去識別化、公開或自製樣稿；正式導入前先確認機關資安規範。

每天 1 小時 × 12 週優化策略

原則：前 4 週建能力、中 4 週接業務、後 4 週建資產。每週最後一天的 1 小時固定做檢核與筆記。

第 1 週
安裝、登入、專用資料夾、基本對話。
claude doctor 全綠、完成 3 次建檔／改檔循環。
第 2 週
CLAUDE.md 個人化＋斜線指令熟練。
任意產出自動符合繁中公文風格。
第 3 週
批次處理入門（練習一、二的前半）。
單指令處理 5 份檔案成功。
第 4 週
格式轉換與多輪修正。
能用 3 輪追問把草稿改到可用。
第 5–6 週
導入第一項真實業務（去機敏化）：週報或會議紀錄自動化。
實際節省時間 ≥ 每週 1 小時。
第 7–8 週
導入第二項業務：歷年文件彙整或用語總校。
完成 1 次 20 份以上批次任務。
第 9–10 週
建置練習三的政策知識庫（分次進行）。
HTML 總覽頁初版完成。
第 11 週
整理「個人指令範本庫」：把 12 週來成功的指令句分類存檔。
範本 ≥ 10 條，任一條可直接複用。
第 12 週
成果總結：向同仁展示知識庫與工作流，蒐集回饋、規劃下一階段。
完成 1 場 15 分鐘內部分享。

實際應用案例（台灣情境）

案例｜出國考察報告的資料整併

場景：赴日考察救護制度返國後，手上有 20 份零散素材——每日筆記、機構簡介、拍攝的簡報照片文字檔、交流會議紀錄，須於兩週內繳交出國報告。做法：將全部素材放入 C:\claude-work\出國報告，請 Claude Code 先產出「素材總表」，再依「行程紀要／制度觀察／與我國比較／建議事項」四章逐章彙整草稿，最後統一用語與格式。可衡量成果：初稿產出時間由約 3 個工作天縮短至半天，用語一致性一次到位，承辦人只需專注在「建議事項」的政策判斷——把時間花在機器做不到的事情上。
