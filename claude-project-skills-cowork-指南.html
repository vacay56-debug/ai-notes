CLAUDE-REF-115-002｜內部參考文件

Claude Project × Skills × Cowork
完整比較指南

三種能力的定位、設定方式與進階要點 —— 依消防署救護科實務情境增補

參考用
壹

一句話定位

三者並非互斥選項，而是三個不同層次的工具：Project 是「工作空間」、Skills 是「自動觸發的作業程序」、Cowork 是「自主執行的代理人」。實務上經常三者併用。

PROJECT｜專案

持久性工作空間

Claude 在同一 Project 內的每次對話中，持續掌握你上傳的檔案、指示與語氣設定。

類比：一個常設的業務卷宗，資料與脈絡都放在裡面。
SKILLS｜技能

自動載入的指令集

預先寫好的作業說明，當 Claude 偵測到相關任務時自動啟用。寫一次，每次都生效。

類比：一份標準作業程序（SOP），觸發條件到了就自動套用。
COWORK｜協作代理

桌面自主代理

讀取你的檔案、自行規劃、逐步執行，最後交付完成品，過程中不需逐句對話。

類比：一位可交辦整案的承辦同仁，交付成果而非逐段回覆。

參

逐項詳解

一、Project（專案）

persistent workspace

是什麼

一個持久存在的工作空間。上傳到 Project 的檔案、寫在 Project instructions 的規則，會套用到該 Project 內的每一次對話，不必每次重新交代背景。

最適合

  • 需要固定口吻、固定格式的反覆性文書工作。
  • 圍繞同一批參考資料進行的長期業務（如同一法規研修案、同一年度計畫）。

設定步驟

  1. 上傳 20 至 30 份最具代表性的過往文件，作為口吻與格式範例。
  2. 撰寫 Project instructions：明確界定對象輪廓、語氣規則、禁用詞句。
  3. 上傳相關規範文件與標準作業程序（Standard Operating Procedure, SOP）。

多數人不知道的事

  • 指示要短：過長的 instructions 會被略讀，重點反而被稀釋。
  • 一份整理好的檔案，勝過一堆零散上傳：先自行彙整再上傳，效果遠優於把原始資料全部倒進去。
  • 記憶隔離：同一 Project 內的對話互通記憶，但該記憶與其他 Project 完全隔離——適合用來區隔不同業務流（如 EMS 政策與採購案分開建 Project）。

二、Skills（技能）

auto-loading instruction set

是什麼

一組儲存好的作業指令（SKILL.md 加上選用的參考檔案），當 Claude 偵測到相關任務時自動載入。寫一次，之後每次觸發都自動套用，不必重複說明。

最適合

  • 每週需要向 Claude 交代一次以上的固定任務。
  • 步驟固定、格式固定、否則每次都得重新解釋的多步驟流程（如公文三段式架構、預算書格式）。

設定步驟

  1. 請 Claude（或 Cowork 內建的 skill-creator）協助建立 Skill 骨架。
  2. 回答建置提問時務必具體：模糊的回答只會產出模糊的 Skill。
  3. 打包為 ZIP 上傳（Settings → Capabilities → Skills），注意 SKILL.md 必須位於 資料夾名稱/SKILL.md 這一層，不可多包一層。
  4. 桌面版亦可直接放置於 %USERPROFILE%\.claude\skills\（隱藏資料夾）。

多數人不知道的事

  • Skills 是省 token，不是花 token：採漸進式揭露（progressive disclosure），未觸發的 Skill 不佔上下文，因此安裝多個 Skill 不會等比例增加消耗。
  • 「不適用於」比「適用於」更重要：description 是觸發開關，負面條件（do NOT use for）決定 Skill 會不會誤觸發、跨業務流互相干擾。例：EMS 研究 Skill 應明確排除 CIT（Crisis Intervention Team，危機介入小組）政策內容，避免跨到警政、衛政權責範圍。
  • Cowork 工作階段可轉存為 Skill：任何一次成功的 Cowork 會話，可從會話選單直接轉為可重用的 Skill。
常見誤區：Skill 寫好卻從不觸發，九成原因是 description 寫得太抽象。應直接列出使用者會說出口的字眼（如「寫公文」「編預算」「做簡報」）作為觸發詞。

三、Cowork（協作代理）

desktop agent

是什麼

桌面端的自主代理。指派任務後，它會讀取指定資料夾內的檔案、自行擬定執行計畫、逐步完成，最後交付完成品（檔案、報告、簡報），而非逐段對話回覆。

最適合

  • 有明確交付物的複雜任務（完整報告、成套簡報、多檔整合）。
  • 希望「交辦後離開」的例行性工作，不必全程守在對話框。

設定步驟

  1. 建立 Cowork 工作資料夾，內含三個子資料夾：background（背景資料）、outputs（產出）、templates（範本）。
  2. 放入數份背景檔案：說明你是誰、你的口吻、你所屬機關的脈絡。
  3. 設定全域指示（Global Instructions），要求 Claude 在每項任務開始前先檢視背景檔案。

多數人不知道的事

  • 長會話燒 token 很快：任務完成後應即關閉會話，不要在同一會話中無限延伸。
  • 成功的會話要存成範本：任何一次執行得好的任務，結束時請 Claude 把該次的結構存為可重用範本，下次直接套用。
  • ABOUT ME 不會自動被讀取：Cowork 讀取個人背景檔，是因為你在 Global Instructions 中明確要求它讀；沒寫，它就不讀。
釐清：Cowork 與 Claude Code 為不同產品。/loop、/goal、routines 等指令屬於 Claude Code（終端機／開發者導向）；Cowork 為知識工作導向的桌面代理。兩者皆可使用相同格式的 SKILL.md。
肆

快速決策：我該用哪一個？

問一
這件事需要固定的背景資料與一致口吻，且會反覆進行？
是 → 建 Project，把資料與指示放進去，之後所有相關對話都在裡面進行。
問二
這是一套固定流程，每週會交代 Claude 一次以上？
是 → 寫成 Skill，讓它自動觸發，不必每次重新解釋步驟與格式。
問三
這件事有明確的交付物，而且我想交辦後就去做別的事？
是 → 交給 Cowork，讓代理自行讀檔、規劃、執行、交付。
併用
三者可以疊加使用
最完整的組態：Project 提供業務脈絡 ＋ Skills 提供格式與程序 ＋ Cowork 負責整案執行。Skill 在三種環境中皆可觸發，是三者之間的共通元件。
伍

救護科實務對應

以本科現行業務為例，說明三種工具的分工方式：

Project「緊急醫療救護法研修案」專案

上傳現行法規、歷次修法紀錄、各國制度比較資料與科內既往簽稿，撰寫指示界定引用格式與用語規範。研修案相關的所有對話集中於此，記憶互通且與採購、預算等其他業務隔離。

Skills現行 nfa-* 技能組

公文起草（nfa-gongwen）、預算書撰寫（nfa-budget-doc）、政策簡報（nfa-policy-slides）、採購文件（nfa-procurement）、國際 EMS 研究（nfa-ems-research）、出國報告（nfa-overseas-report）等，各以具體業務用語作為觸發詞，並以負面條件區隔業務流（如 EMS 研究 Skill 排除 CIT 政策內容）。

Cowork「韌性國家醫療整備計畫」季報產製

建立含背景資料、範本、產出三個子資料夾的工作區；交辦後由代理讀取執行進度資料、依範本產出季報初稿與簡報，承辦人僅需最終審校。執行順利的一次會話，即轉存為範本或 Skill 供下季重用。

整合工作流

Claude 建立分析架構與初稿 → NotebookLM 以原始文獻進行事實查證（尤其日文資料）→ Claude 依 Skill 產出正式文書 → Gamma 產製視覺簡報。Project 承載脈絡、Skills 承載程序、Cowork 承載執行，各司其職。
